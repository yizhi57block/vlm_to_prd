# 2. 产品定位与目标

## 2.1 产品定位

MercuryDynamic 是面向海外红人营销团队的业务操作平台，以“客户—项目—需求工单—执行工单—红人合作”为主线，覆盖红人筛选、Outreach、回复与提报、报价压价、履约、内容上线、数据监控和付款记录。

它同时承担三类系统能力：

1. 客户与项目 CRM；
2. 以工单和状态驱动的红人营销履约系统；
3. 红人资产、邮件往来和业务统计的统一工作台。

## 2.2 产品目标

- 将非结构化的红人招募需求转换为可审核、可执行的筛选条件；
- 通过 AI 每日捞取、AI 查询、人工审核和资料库复用提升选人效率；
- 通过阶段化 OR 工作台、模板和批量操作提升建联转化效率；
- 将合作确认后的寄样、合同、内容、上线、监控和付款收口到同一红人履约档案；
- 建立可追溯的状态、价格、文件、操作和统计口径。

## 2.3 原型成熟度边界

原型可用于确认页面结构、字段、状态、主要操作和联动意图，但以下内容仍属待设计/待实现：

- 永久化存储、真实鉴权、服务端权限和审计日志；
- 真实邮件收发、限流、送达与失败重试；
- 真实 AI 语义解析、跨平台检索与匹配度计算；
- 社交平台数据采集、内容监控与物流查询；
- 文件上传、下载、版本与存储安全；
- 汇率、销售额、毛利、回款与绩效口径；
- 原型中以“Mock”弹窗表达的导入、导出、上传和采集结果。

# 3. 产品范围

- 账号密码 + 图形验证码登录；
- 微信扫码登录入口；

# 4. 用户与权限

## 4.1 原型已验证账号

| 账号类型 | 登录后首页 | 可见能力 | 受限能力 |
|---|---|---|---|
| OR 运营 | 经营看板 | 原型中的所有可见导航 | 无额外隐藏视图 |
| 执行运营 | 执行工单 | 客户、项目、需求/执行工单、已办、邮件回复、资料库、AI 查询、迷路邮件、统计 | OR 工单、运营工单菜单隐藏，直接访问也应被拦截 |

## 4.2 业务角色

原型数据中出现 OR 运营、项目经理、销售/商务、内容运营、财务、系统管理员和管理层。这些角色可作为后续 RBAC 设计的候选角色，但除上述两个登录账号外，当前原型没有验证它们的菜单和操作权限。

## 4.3 权限实现要求

- 菜单隐藏不能代替服务端鉴权；
- 所有页面路由、查询、导出和写操作均需独立校验权限；
- 价格、毛利、付款、合同、客户联系方式应支持字段级权限；
- 主运营、副运营、项目经理和归属团队用于数据范围过滤；
- 状态、价格、合同、付款、邮件关联和红人主数据修正必须审计。

# 6. 核心业务对象与关系

| 对象 | 定义 | 关键关系 |
|---|---|---|
| 客户 | 采购红人营销服务的品牌/企业 | 1:N 联系人，1:N 项目 |
| 项目 | 预算、平台、周期、执行和核算的上层容器 | 必须关联客户；可有多张执行工单和多位红人 |
| 需求工单 | 独立的红人筛选条件和数量要求 | 先审核，后由执行工单绑定到项目 |
| 执行工单 | 将已通过/执行中的需求与项目、主/副运营关联 | 提供项目级统一工作台 |
| 红人 | 按社交平台管理的创作者主数据 | 以“平台 + 平台账号 ID”作为业务唯一标识 |
| 项目红人 | 某红人在某项目中的候选、OR、商务和履约实例 | 状态、跟进、报价和履约应与项目维度绑定 |
| 邮件会话 | 与红人往来的 OR 与回复邮件链 | 关联红人、项目、工单和负责人 |
| 履约档案 | 合作确认后的红人执行容器 | 包含寄样、合同、内容、上线、监控、财务和操作记录 |
| 付款计划 | 面向某项目合作红人的应付记录 | 可有首款、尾款、全款、追加款 |

# 7. 端到端业务流程

```text
客户/联系人建档
  → 创建项目
  → 创建需求工单（可保存草稿）
  → 需求审核（通过 / 退回）
  → 通过后 AI 按日捞取候选
  → 创建执行工单，绑定需求 + 项目 + 主/副运营
  → 备选红人入池（AI / 手工 / 导入 / 资料库复用）
  → 补充邮箱
  → 人工审核（通过 / 人工不符 / AI 不符）
  → 选择模板并批量 OR
  → 未回复追发 / 重发
  → 回复聚合与意向判定
  → 提报项目侧
  → 报价 / 压价 / 最终确认价
  → 合作确认，自动进入运营履约
  → 选品寄样
  → 合同签署
  → 内容执行
  → 上线与监控
  → 付款归档
  → 已完成 / 已取消
```

关键衔接规则：

- 需求工单审核通过后才能被选入执行工单；
- 创建执行工单时必须选择项目并指定至少 1 名主运营；
- 红人有效邮箱是邮件 OR 的前置条件；
- 红人审核通过后进入待 OR，不符则进入回收；
- 邮件回复可从回复聚合页或完整会话抽屉中提报；
- 合作确认后红人自动出现在运营工单；
- 上线监控任务保存后，运营状态联动为“已上线”；
- 付款完成后记录从未完成集合进入已支付归档。

# 8. 功能需求

## 8.1 登录与全局框架

### GLO-001 账号登录

- 输入用户名、密码和 4 位图形验证码；
- 验证码排除易混淆字符，点击可刷新；
- 缺少账号/密码、验证码错误、账密错误均需给出明确错误文案；
- 登录成功后根据账号类型进入首页或执行工单；
- 退出后返回登录页并刷新验证码。

### GLO-002 微信扫码登录

- 登录页可在账号登录和微信扫码之间切换；
- 当前原型为“模拟扫码成功”，真实微信 OAuth/企微鉴权方案待确认。

### GLO-003 全局导航与页签

- 左侧导航按业务分组，父级菜单可展开/收起；
- 打开的页面进入顶部页签栏，首页不可关闭，其他页签可关闭；
- 关闭当前页签后返回前一页签；
- 页面切换后主内容回到顶部；
- `Esc` 关闭弹层、抽屉和顶部弹出层。

### GLO-004 全局搜索

- 支持搜索页面、红人 ID/昵称、项目和需求工单；
- 搜索结果最多展示 12 条，显示结果类型并跳转对应页面；
- 无结果时显示空状态；
- 生产实现不应仅使用首次加载的静态索引，新增数据应可被检索。

### GLO-005 通知与待办

- 通知铃显示未读标识，支持单条已读和全部已读；
- 通知可跳转到邮件回复、需求审核、付款、迷路邮件或运营工单；
- 付款独立页当前不在交付范围，通知的付款跳转目标必须改为可用的红人履约详情，或在明确建设独立财务页后跳转该页面。

### GLO-006 快速新建

- 顶栏“新建工单”仅包含“需求工单”和“执行工单”两个入口；
- 入口需按权限和对象可用性禁用或隐藏。

## 8.2 首页经营看板

### HOM-001 周期切换

支持自然周、自然月、自然季和自然年，默认自然月。所有 KPI、趋势、排行和漏斗应同步切换周期，原型当前只替换了选中态，生产实现需联动数据。

### HOM-002 KPI 卡片

- 销售额：按 USD 折算，显示环比；
- 签约订单量；
- 支付笔数/已付金额及临期提示；
- 上线视频数、总播放和按时上线率。

### HOM-003 趋势与漏斗

- 近 12 个周期的签约金额与上线视频金额趋势；
- 红人转化漏斗按去重红人数展示“候选 → 上线”；
- 附加显示 OR 回复率、提报通过率和签约率。

### HOM-004 排行、待办和进行中项目

- 销售排行支持跳转销售统计；
- 待办项支持直达需求审核、OR 回收/滞留等对应上下文；
- 进行中项目支持跳转项目列表或打开项目详情。

## 8.3 客户与联系人

### CRM-001 客户列表

- 按客户全称/简称、等级、商务归属筛选；
- 展示全称、简称、S/A/B 等级、企业地址、项目经理、商务归属、项目数、状态；
- 支持新增、编辑、导出、分页；
- 已被项目引用的客户不得物理删除，仅可停用。

### CRM-002 新增/编辑客户

| 字段 | 要求 |
|---|---|
| 客户全称 | 必填，建议唯一性校验 |
| 客户简称 | 选填，空值时可回退为全称 |
| 客户等级 | S/A/B |
| 企业地址 | 国家/城市/详细地址 |
| 项目经理 | 单选 |
| 商务归属 | 单选 |
| 联系人 | 可在客户表单内连续新增姓名、手机、邮箱 |

### CRM-003 联系人列表与编辑

- 一个客户可关联多个联系人；
- 按姓名/手机/邮箱和所属客户筛选；
- 字段包含所属客户、姓名、职务、手机、邮箱、是否主要联系人、最近跟进；
- 所属客户、姓名、手机在原型上标记为必填，生产实现应校验手机和邮箱格式；
- 同一客户的“主要联系人”是否唯一待确认。

## 8.4 项目管理

### PRJ-001 项目列表

- 按项目名称、客户、状态、项目经理筛选；
- 展示项目名称/编号、客户、预算、推广平台、项目周期、项目经理、状态；
- 项目状态为进行中、暂停、结束；
- 支持详情、编辑和跳转需求工单。

### PRJ-002 新建/编辑项目

| 字段 | 要求 |
|---|---|
| 关联客户 | 必填 |
| 项目名称 | 必填 |
| 预算金额 | 数值，建议非负 |
| 币种 | USD / EUR / RMB |
| 开始日期、结束日期 | 结束日期不得早于开始日期 |
| 项目经理 | 单选 |
| 项目状态 | 进行中 / 暂停 / 结束 |
| 推广平台 | Instagram / YouTube / TikTok，多选，至少 1 项 |

### PRJ-003 项目详情

- 抽屉展示客户、预算、周期、项目经理、平台和状态；
- 管理项目需求文档，展示文件名、格式、上传人和上传时间，支持上传/下载；
- 展示项目内红人数及最多 6 个预览，显示红人当前阶段；
- 项目无红人时给出前往 OR 工单的空状态提示。

## 8.5 需求工单

### DEM-001 需求工单列表与 KPI

- KPI：待审核、已通过·捞取中、已退回、今日 AI 捞取候选；
- 按工单号/名称、状态、平台筛选；
- 展示工单号、名称/创建时间、关联项目、平台、目标数量、已捞取数、紧急程度、状态；
- 待审核工单可审核，所有工单可查看条件和前往执行工单。

### DEM-002 新建需求工单

| 字段 | 要求 |
|---|---|
| 工单号 | 系统自动生成 |
| 工单名称 | 必填 |
| 紧急程度 | 普通 / 紧急 / 特急 |
| 平台 | Instagram / YouTube / TikTok，原型为单选 |
| 目标红人数量 | 必填，正整数 |
| AI 每日捞取数量 | 可选，正整数 |
| 粉丝量区间 | 10 万以下 / 10–50 万 / 50–100 万 / 100 万以上，可多选 |
| 合理均播区间 | 不限 / 1–10 万 / 10–50 万 / 50 万以上 |
| 国家/地区 | 可输入多个 |
| 语言 | 英语 / 西班牙语 / 德语 / 法语 |
| 最新视频时间 | 近 15 / 30 / 90 天 |
| 一级/二级品类 | 二级品类应随一级品类联动 |
| 关键词 | 支持多关键词 |
| AI 内容标签 | 支持多标签 |
| Amazon Store Link | 选填，需校验 URL |

表单支持取消、保存草稿和提交审核。注意：新建表单不包含项目字段，需求与项目的正式绑定发生在执行工单。列表中的“关联项目”应在未绑定时显示“待绑定”，不得默认写入某个项目。

### DEM-003 需求审核

- 待审核工单可选择“通过”或“退回”；
- 退回时审核意见必填，通过时可选；
- 通过后工单进入已通过，AI 开始按日捞取；
- 退回后记录原因并允许修改后重新提交（重新提交交互待补）。

## 8.6 执行工单

### EXE-001 新建与分配

- 工单号自动生成；
- 只能选择状态为已通过或执行中的需求工单；
- 必须关联项目，系统校验需求的平台/条件与项目是否匹配；
- 主运营支持多选但至少 1 人，副运营可多选；
- 可填写执行要求/注意事项；
- 创建后通知主运营和副运营。

### EXE-002 项目树与工作台概览

- 左侧项目树按客户分组，支持搜索项目；
- 项目节点显示项目状态和项目内红人数；
- 项目头部显示客户、周期、项目经理和项目状态；
- 提供项目协作表、项目文件入口；
- KPI：OR 阶段数、待审核数、审核完成数、运营中数。

### EXE-003 执行页签

| 页签 | 归入规则/功能 |
|---|---|
| 备选 | 候选、待审核、待补邮箱；卡片展示三个内容缩略图、粉丝、均播、互动率等 |
| 售前&压价 | 待 OR、未回、回复、提报、压价中 |
| 运营 | 合作确认后的红人履约信息 |
| 项目文件 | 项目文件聚合；当前原型为静态/预留内容 |
| 运营库 | 当前为预留页签，不具备可验收内容 |
| 回收 | 回收、滞留的红人 |

### EXE-004 执行工单红人详情

- 备选卡片可打开红人详情弹窗；
- 详情包含运营、数据、记录等页签，与红人共用抽屉的信息应保持同源；
- 从执行工单修改红人信息应同步到 OR、资料库和运营工单。

## 8.7 OR 工单

### OR-001 阶段导航与项目树

- 阶段条为：候选、待补邮箱、待审核、待 OR、未回、回复、提报、压价中、合作确认、回收/滞留；
- 各阶段显示当前数量，点击后筛选右侧列表；
- 项目工单树支持全部展开/折叠，按项目过滤红人；
- 显示当前项目 OR 回复率和提报通过率。

### OR-002 红人列表与筛选

- 按红人 ID/邮箱/关键词、平台、建联状态、国家/地区筛选；
- 展示红人、平台、粉丝量、合理均播、邮箱、跟进次数、最近动态和行级操作；
- 支持单选、当页全选、清除选择和分页；
- 批量操作条包含发送 OR、一键追发、一键重发、一键 PASS、批量恢复；
- 不适用于当前阶段的操作应禁用或隐藏，不应所有阶段都展示同一组操作。

### OR-003 邮箱补充与校验

- 缺少邮箱的红人进入“待补邮箱”；
- 保存时校验邮箱格式；
- 邮箱有效后状态从待补邮箱进入待审核，并回写资料库。

### OR-004 红人审核

- 审核结果：通过、人工不符、AI 不符；
- 不符时原因必填，通过时可选；
- 通过后进入待 OR；人工不符/AI 不符进入回收；
- 保留审核人、时间、结果和原因。

### OR-005 OR 模板

- 模板列表展示模板名称、使用次数、回复率和当前选中态；
- 编辑字段：模板名称、邮件标题、富文本正文、附件；
- 支持变量：`{红人昵称}`、`{品牌名}`、`{产品链接}`；
- 需对必填变量、未知变量和空变量进行校验。

### OR-006 批量发送

- 展示目标红人数、发送账号和预计耗时；
- 原型表达的限流为 30 封/分钟，真实限额应配置化；
- 发送前必须选择模板并预览第 1 位红人的变量替换结果；
- 未解析变量必须拦截，不得静默发送；
- 默认跳过 30 天内已发送过的红人；
- 发送后记录成功、失败、跳过明细和失败原因；
- 发送成功的红人进入未回，建联状态变为已发 OR。

### OR-007 回复、提报、报价与压价

- 收到邮件后进入回复阶段和邮件回复聚合页；
- 可从完整会话中“提报该红人”，状态从回复进入提报；
- 报价类型为红人报价、运营压价、最终确认价；
- 每条价格记录包含金额、币种、明细/理由、记录人和时间；
- 价格历史不可覆盖，按时间倒序；
- 运营压价后报价状态为压价中；最终确认价应将红人转入合作确认，该联动在原型中未完整实现，需开发补齐。

### OR-008 回收与滞留

- PASS、人工不符和 AI 不符进入回收；
- 超时未流转的红人可进入滞留，原型示例为超 15 天，真实阈值待确认；
- 回收/滞留区支持批量恢复；
- 恢复到哪个阶段应依原因和上一有效状态决定，需保留恢复日志。

## 8.8 运营工单与红人履约

### OPS-001 运营工单概览

- KPI：运营中、已上线、已完成、待提交付款；
- 左侧按客户/项目组织，支持搜索、展开和收起；
- 仅显示存在合作红人的项目；
- 按红人 ID/昵称、运营状态、财务状态筛选；
- 列表展示红人、平台、总价、合理均播、运营负责人、运营状态、财务状态、最近记录；
- 支持详情、编辑运营信息、查看沟通和导出。

### OPS-002 运营状态与负责人

- 运营状态：运营中、已上线、已完成、已取消；
- 可更换运营负责人并填写变更备注；
- 状态变更写入运营记录，并同步列表和履约进度；
- 已完成/已取消后是否允许逆向修改待确认。

### OPS-003 履约概览与基础信息

- 履约流程节点：确认合作 → 选品寄样 → 签约 → 内容执行 → 上线监控 → 付款归档；
- 基础信息包含平台账号 ID、主页链接、邮箱、国家/语言、粉丝量和博主类型；
- 平台账号 ID 不可直接编辑；
- 修改会回写红人资料库并保留修改前后值；
- 概览中显示 OR 阶段、邮箱、建联和报价状态。

### OPS-004 基本修正与红人画像

- 显示性别占比、年龄段占比和地区 TOP5；
- 占比总和应接近 100%，超出容差时提示；
- 显示全部视频、近 15 条、近 20 条、去置顶合理均播及互动率；
- 显示数据更新时间和数据来源，支持重新采集；
- 允许人工修正互动率、近 15 条均播、去置顶均播，并审计前后值。

### OPS-005 内容运营记录

- 记录分类：内容沟通、选品寄样、合同、上线、财务、其他；
- 支持提醒项目经理、主运营、财务或不提醒；
- 支持基础富文本格式；
- 记录按时间倒序，包含类型、内容、记录人和时间；
- 状态变更、寄样、合同、上线和付款事件应自动写入。

### OPS-006 选品与寄样

- 字段：选品内容、寄样状态、收件人、快递单号、收件地址；
- 寄样状态：待寄出、已寄出、已签收、异常；
- 保存后写入运营记录；
- 物流轨迹自动查询在原型中明确标记为待确认，当前不作强制交付。

### OPS-007 合同

- 字段：合同发送日期、签署日期、付款周期、预计付款日期；
- 付款周期候选：签约后 7 日、上线后 15 日、月结 30 天；
- 支持上传新版本、下载和历史版本查看；
- 替换合同不得覆盖历史文件；
- 签署日期和付款周期变更需同步预计付款日期。

### OPS-008 上线与监控

- 支持查看数据、编辑监控和新增上线监控；
- 视频地址必填，并应校验与所选平台域名匹配；
- 字段：平台、发布时间（原型为 PST）、监控开始/结束、Spark Ad Code、甲方官方 Link；
- 勾选项：最终定稿已确认、上线共创、文案 Tag 一致；
- 保存监控任务后运营状态变为已上线；
- 原型表达每 6 小时同步一次，支持立即同步；
- 指标：播放、点赞、评论、分享；
- 支持上传 Story/Reel 截图证据；
- 监控频率、可监控指标及平台 API 可用性需技术评估。

### OPS-009 压价、报价、沟通与其他

- 压价页签展示运营压价记录，支持新增；
- 报价页签展示当前总价、报价状态、最近变更和全部价格历史；
- 沟通页签显示收/发件摘要，可打开完整会话；
- 其他信息包含紧急程度、下次跟进日期和备注。

## 8.9 邮件回复与沟通

### MAIL-001 回复聚合

- 聚合需要运营处理的红人回复；
- 按红人 ID/主题和意向筛选；
- 意向：有兴趣、询价、婉拒、需补充信息；
- 展示红人、工单名称、最新主题、意向、往来邮件数、最后收邮时间、负责人；
- 支持邮件详情和直接提报。

### MAIL-002 完整会话

- 按时间展示收件/发件、发件人、收件人、主题、正文和时间；
- 支持回复、添加附件、保存草稿和发送；
- 发送空正文时必须拦截；
- 支持从会话中提报红人；
- 应保存 Message-ID、In-Reply-To、References 等邮件线索，以便稳定串联会话。

## 8.10 已办

### DONE-001 已办归档

- 归档已完成的需求审核、OR 发送、提报审核、合同签署、付款完成和内容上线事项；
- 按单号/名称/红人和事项类型筛选；
- 展示单号、类型、事项、关联项目、操作人、完成时间和结果；
- 记录不应允许直接修改，如需更正应生成追加审计记录。

## 8.11 红人资料库

### INF-001 分平台资料库

- Instagram、YouTube、TikTok 各有独立列表，字段和交互保持一致；
- 按红人 ID/昵称/邮箱、国家地区、粉丝量区间、博主类型、建联状态和报价状态筛选；
- 展示红人、邮箱、国家/语言、粉丝量、合理均播、互动率、建联状态、报价状态；
- 支持新增、批量导入、按当前筛选导出、详情和编辑。

### INF-002 新增红人

| 字段 | 要求 |
|---|---|
| 平台 | 必填，IG/YT/TT |
| 平台账号 ID | 必填，与平台组合唯一 |
| 主页链接 | 必填，需校验平台域名 |
| 邮箱 | 选填，填写时需校验格式 |
| 国家/地区、语言、博主类型 | 选择字段 |
| 粉丝量、合理均播 | 非负整数 |

新增后进入候选，建联状态为未建联，报价状态为未报价。生产实现必须显式选择加入哪个项目/候选池，不得像原型 Mock 那样固定加入某项目。

### INF-003 批量导入

- 导入流程：模板校验 → 字段校验 → 唯一性校验 → 导入 → 失败明细；
- 重复数据应允许选择跳过、补全空字段或更新，默认不覆盖人工修正值；
- 导入结果应包含成功、跳过、失败数量和可下载失败明细。

## 8.12 AI 查询

### AI-001 自然语言条件解析

- 支持解析平台、国家、语言、粉丝量、均播、品类、内容标签和最近更新时间；
- 提供示例查询，点击后直接执行；
- 将解析结果以条件签展示，让用户可核对；
- 查询结果显示命中数和耗时。

### AI-002 检索结果

- 展示红人、平台、国家/语言、粉丝量、合理均播、AI 内容标签和匹配度；
- 支持多选、全选、查看详情和加入项目候选池；
- 加入前必须选择项目/执行工单，检查是否已存在，并返回成功/重复/失败明细；
- 匹配度必须有可解释的计算口径，不得只展示无来源的百分比。

## 8.13 红人履约内的付款

### PAY-001 新增付款计划

- 关联合作红人/运营工单，必填；
- 付款类型：首款、尾款、全款、追加款；
- 币种：USD、EUR、RMB；
- 金额必填且不得为负；
- 字段包含计划付款日期、备注、发票/付款凭证；
- 支持 PDF/JPG/PNG，删除和替换保留审计记录；
- 创建后财务状态为待提交，并更新运营工单最近记录。

### PAY-002 付款状态

```text
待提交 → 财务支付中 → 付款完成
```

- 付款详情展示单号、金额、客户/项目、红人/类型、状态轨迹和凭证；
- 待提交可标记为财务支付中；
- 未完成状态可确认付款完成，同时记录实际付款时间并归档；
- 状态逆转、驳回、撤销和重开规则待确认；
- 当前无独立财务列表可验收，付款记录应从红人履约详情访问。

## 8.14 迷路邮件

### LOST-001 自动匹配

匹配优先级为：

1. 会话标识；
2. 邮箱地址；
3. 邮件主题标识；
4. 人工匹配。

同一邮件关联成功后不得重复出现在迷路列表。

### LOST-002 列表与处理

- 按发件人/主题和未匹配原因筛选；
- 未匹配原因：邮箱未建档、主题无标识、会话已断裂、多人共用邮箱；
- 展示发件人、主题、附件数、接收时间、原因和正文摘要；
- 处理时展示完整邮件，人工选择红人和项目/工单；
- 确认关联后邮件进入红人沟通记录并从列表移除；
- 可标记为无关邮件，但应进入可审计的忽略档案，不得物理删除。

## 8.15 统计

### BI-001 项目统计

- 支持自然周/月/季/年切换和导出；
- KPI：签约金额、推进金额、上线视频金额、待回款/毛利率；
- 客户 → 项目明细可展开；
- 字段：签约红人数、签约金额、推进金额、上线金额、待回款、毛利、毛利率、趋势；
- 跨币种金额按汇率折算为 USD，页面需显示汇率日期和口径。

### BI-002 销售统计

- KPI：签约红人金额、推进金额、上线视频金额、毛利率；
- 趋势对比当期与上一周期，展示签约/推进/上线金额；
- 展示商务人员排行；
- 按客户汇总签约红人、三类金额、毛利率和环比。

### BI-003 运营统计

- 按运营人员展示负责工单、审核红人、已 OR、签约红人、推进中、已上线和 OR 回复率；
- 展示人员绩效排名；
- 当前原型使用“签约 + 推进 + 上线”加权，权重以及是否用于考核待确认；
- 团队漏斗：审核 → OR → 回复 → 提报 → 通过 → 签约 → 上线。

# 9. 状态模型

## 9.1 项目状态

```text
进行中 ↔ 暂停 → 结束
```

结束后是否允许重新打开待确认。

## 9.2 需求工单状态

```text
草稿 → 待审核 → 已通过 → 执行中 → 已完成
             └→ 已退回 → 编辑后重新提交
```

- 原型列表过滤明确包含待审核、已通过、执行中、已完成、已退回；
- 草稿由表单操作推导，需补充草稿列表入口。

## 9.3 OR 主流程

```text
候选
  ├→ 待补邮箱 → 待审核
  └→ 待审核
待审核
  ├→ 待 OR → 未回 → 回复 → 提报 → 压价中 → 合作确认
  └→ 回收
未回 → 滞留（超时规则待确认）
回收/滞留 → 恢复到上一可处理阶段
```

“回复”到“提报”、“提报”到“压价中/合作确认”的项目侧审核节点待补充完整原型。

## 9.4 建联状态

```text
未建联 → 已发 OR → 已回复 → 合作中
```

建联状态是红人的联系进度，不能与项目内的 OR 阶段混用。同一红人参与多个项目时，应以项目红人维度保存建联状态。

## 9.5 报价状态

```text
未报价 → 已报价 → 压价中 → 已确认
```

## 9.6 运营状态

```text
运营中 → 已上线 → 已完成
    └→ 已取消
```

## 9.7 寄样状态

```text
待寄出 → 已寄出 → 已签收
                 └→ 异常
```

## 9.8 付款状态

```text
待提交 → 财务支付中 → 付款完成
```

# 10. 关键业务规则

## 10.1 唯一性与去重

- 客户全称建议在租户内唯一；
- 项目名称建议在客户内唯一；
- 红人业务唯一键为平台 + 平台账号 ID；
- 红人在同一项目中只能存在一个有效实例；
- 邮件 Message-ID 全局唯一；
- 同一红人、同一发送账号、同一项目在 30 天内的重复 OR 默认跳过，但允许有权用户明确重发。

## 10.2 价格、预算和币种

- 原币金额和币种不可丢失；
- 跨币种统计需保存折算汇率、汇率日期和折算值；
- 报价历史只追加不覆盖；
- 最终确认价与合作总价的关系必须唯一明确；
- 付款计划合计超过合作总价时应拦截或进入特批；
- 原型中“待回款”为客户应收口径，但当前没有客户回款模块，统计数据来源待确认。

## 10.3 时间与时区

- 存储建议使用 UTC，展示按用户/项目时区；
- 原型上线时间固定写为 PST，生产版应将时区显式配置，避免夏令时歧义；
- 邮件、合同、寄样、监控、付款和审计时间必须保留时区。

## 10.4 批量操作

- 只对用户明确选中的对象执行；
- 执行前展示数量、影响范围和风险；
- 执行后返回成功、失败、跳过数量和可下载明细；
- 批量 PASS、恢复、发送和重发需记录操作人和批次号；
- 应支持幂等，防止重复点击造成重复邮件或重复数据。

## 10.5 文件

- 项目需求文档、OR 模板附件、合同、上线截图、发票与付款凭证应统一管理；
- 文件记录包含名称、格式、大小、用途、关联对象、上传人、上传时间和版本；
- 合同和财务凭证替换/删除必须保留历史；
- 支持文件类型、大小、病毒、访问权限和下载鉴权校验。

## 11.2 建模原则

- 红人主数据与项目红人过程数据分离；
- OR 阶段、报价、邮件、履约和付款均应绑定 ProjectInfluencer/Fulfillment，避免同一红人多项目串数据；
- 指标数据保留采集时间、来源和人工修正标识；
- 状态不只保存当前值，同时保存状态流转历史；
- 价格、合同版本和凭证使用 append-only 或等价的不可覆盖模型。

# 12. 统计口径

| 指标 | 建议口径 |
|---|---|
| 候选红人 | 指定周期内首次进入项目候选池的去重 ProjectInfluencer 数 |
| 审核数 | 指定周期内完成人工审核的去重项目红人数 |
| 已 OR | 周期内首次发送成功的去重项目红人数 |
| OR 回复率 | 周期内有效回复红人数 / 成功首联红人数 |
| 提报通过率 | 提报通过红人数 / 已完成评估的提报红人数 |
| 签约率 | 已签约红人数 / 合作确认红人数（最终分母待业务确认） |
| 按时上线率 | 按约定时间上线的内容数 / 应上线内容数 |
| 签约金额 | 统计周期内完成签约的合作最终确认价，按指定汇率折算 |
| 推进金额 | 当前处于运营中/已上线但未完成的合作金额（待确认） |
| 上线金额 | 周期内首次上线内容对应的合作金额，避免多内容重复计算 |
| 毛利 | 客户确认收入 - 红人成本 - 可计入的其他成本；收入/成本范围待确认 |
| 毛利率 | 毛利 / 确认收入 |

# 13. 非功能需求

## 13.1 性能

- 普通列表查询 P95 不高于 2 秒；
- 抽屉/弹窗首次打开 P95 不高于 1.5 秒；
- 全局搜索建议 300ms 防抖，返回最多 20 条；
- 大批量导入、邮件发送、数据采集和导出采用异步任务；
- 重列表页必须服务端分页。

## 13.2 可用性

- 所有列表有加载、空、错误、无权限和部分失败状态；
- 保存/发送按钮在请求中禁用，防止重复提交；
- 表单错误需定位到具体字段；
- 弹窗、抽屉支持键盘关闭与焦点管理；
- 批量操作和不可逆的业务变更需二次确认。

## 13.3 安全与合规

- 登录密码不以明文保存，原型内的测试密码不得进入生产；
- 连续登录失败需限流/锁定，会话过期需重新登录；
- 客户联系方式、红人邮箱/地址、合同和财务凭证需加密存储和最小权限；
- 邮件正文、富文本和上传文件需防 XSS/恶意文件；
- 社交平台数据采集必须符合平台条款、隐私法和数据留存政策；
- 数据导出需水印或导出审计。

## 13.4 审计与可观测性

- 记录登录、权限拒绝、状态变更、价格变更、邮件发送、人工关联、文件变更和付款操作；
- 邮件、AI 捞取、社媒采集、监控、导入导出任务需有成功率、耗时、重试次数和错误原因；
- 状态修改应可从业务详情中查看操作轨迹。

## 13.5 兼容性

- 优先桌面 Web，建议最小内容宽度 1280px；
- 支持最新两个主版本的 Chrome、Edge 和 Safari；
- 狭屏下容器支持水平滚动，不得丢失操作列。

# 14. 核心验收标准

## AC-01 登录与权限

1. 账号、密码、验证码均正确时才能登录。
2. 执行运营登录后首页为执行工单。
3. 执行运营不显示 OR/运营工单菜单，且直接输入路由也无法访问。
4. 退出后受保护页面不可继续访问。

## AC-02 客户到执行工单

1. 可创建客户、多个联系人和多平台项目。
2. 新建需求工单可保存草稿或提交审核。
3. 退回需求时无审核意见不可提交。
4. 只能使用已通过/执行中需求创建执行工单。
5. 执行工单无主运营时不可创建。
6. 需求与项目不匹配时进行拦截并说明原因。

## AC-03 备选到 OR

1. 无邮箱红人无法发送 OR，补充有效邮箱后进入待审核。
2. 审核通过进入待 OR，不符进入回收并保留原因。
3. 批量 OR 发送前展示目标数、发送账号、模板和变量预览。
4. 存在未解析变量时不可发送。
5. 默认跳过 30 天内已发送对象。
6. 发送后可查看成功、失败和跳过明细，成功对象进入未回。

## AC-04 回复到合作确认

1. 新回复自动关联正确红人、项目和会话。
2. 回复聚合页可按意向过滤并打开完整会话。
3. 可在会话中回复、存草稿、添加附件和提报。
4. 价格变更不覆盖历史，可查看完整报价/压价轨迹。
5. 最终确认价后红人进入合作确认，并自动生成运营履约档案。

## AC-05 履约与上线

1. 运营工单可按客户/项目和运营/财务状态筛选。
2. 可更换运营负责人，并留存变更前后值和备注。
3. 寄样、合同、内容记录、上线和付款数据均关联到同一履约档案。
4. 合同替换后旧版本仍可下载。
5. 无视频地址时不可保存监控任务。
6. 保存监控任务后运营状态为已上线，并可查看数据与截图证据。

## AC-06 付款

1. 新增付款必须关联合作红人，金额不得为负。
2. 付款状态按待提交 → 财务支付中 → 付款完成流转。
3. 完成时记录实际付款时间，且运营工单财务状态同步更新。
4. 凭证删除/替换保留审计历史。
5. 独立财务页不在当前交付范围，不将其列表和 KPI 作为验收项。

## AC-07 迷路邮件

1. 无法自动匹配的邮件进入迷路列表并标记原因。
2. 可人工选择红人和项目/工单完成关联。
3. 关联后邮件仅出现于目标会话，不再出现于迷路列表。
4. 标记无关邮件保留操作记录并可追溯。

## AC-08 统计一致性

1. 周/月/季/年切换后所有指标同步刷新。
2. 首页、项目统计、销售统计和运营统计在相同口径下结果一致。
3. 去重对象、时间区间、状态时点和汇率日期均可追溯。
4. 导出结果与当前筛选条件和页面汇总一致。

# 17. 版本结论

MercuryDynamic V2 以两个主工作台为产品核心：

1. **执行工单项目工作台**：从备选筛选、审核、OR、回复、提报和压价，一直衔接到运营；
2. **红人履约档案**：从合作确认、寄样和签约，一直到上线监控和付款归档。

客户、项目、需求工单、资料库、邮件和统计是这两个工作台的主数据与横向支撑。独立财务页、运营库、项目品类和项目库不在当前确定交付范围，如要纳入 V2，需先完成业务范围确认。
